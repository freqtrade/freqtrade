# 杠杆交易

!!! Note "同一账户运行多个机器人"
    你不能在同一个账户上使用杠杆运行 2 个机器人。对于杠杆/保证金交易，freqtrade 假定它是该账户的唯一使用者，所有清算水平均基于此假设计算。

!!! Danger "杠杆交易风险极高"
    除非你的策略在现货市场的实盘中已展现出正面结果，否则不要使用大于 1 的杠杆进行交易。请检查策略的止损设置。如果杠杆为 2，0.5（50%）的止损太低，这些交易在达到该止损之前就会被清算。
    对于使用本软件或此模式可能导致的任何损失，我们不承担任何责任。

    请仅在了解 freqtrade（以及你的策略）如何运作的情况下使用高级交易模式。
    此外，永远不要冒超过你承受能力的风险。

如果你已有现有的策略，请阅读[策略迁移指南](strategy_migration.md#strategy-migration-between-v2-and-v3)，将你的策略从 freqtrade v2 策略迁移到可以进行做空和期货交易的 v3 策略。

## 做空

当 [`trading_mode`](#杠杆交易模式) 设置为 `spot` 时，无法进行做空交易。要做空交易，`trading_mode` 必须设置为 `margin`（当前不可用）或 [`futures`](#futures)，同时 [`margin_mode`](#保证金模式) 设置为 [`cross`](#全仓保证金模式) 或 [`isolated`](#逐仓保证金模式)。

策略要做空，策略类必须设置类变量 `can_short = True`。

请阅读[策略定制](strategy-customization.md#entry-signal-rules)以了解如何设置进入和退出做空交易的信号。

## 理解 `trading_mode`

可选值为：`spot`（默认）、`margin`（*当前不可用*）或 `futures`。

### Spot（现货）

常规交易模式（低风险）

- 仅限做多交易（不支持做空交易）。
- 无杠杆。
- 无清算。
- 盈利/亏损等于资产价值的变化（减去交易手续费）。

### 杠杆交易模式

使用杠杆时，交易者从交易所借入资金。这些资金必须全额归还给交易所（可能包含利息），交易者保留使用借入资金进行的任何交易的利润，或承担其损失。

由于资金必须被归还，当杠杆账户中的资产总价值下降到某一点（损失总额小于交易者在杠杆账户中实际拥有的抵押品价值时），交易所将**清算**（强制卖出交易者的资产）使用借入资金进行的交易，以确保交易者有足够的资金偿还借来的资产。交易所还会收取**清算手续费**，增加交易者的损失。

因此，**如果你不完全清楚自己在做什么，请不要使用杠杆交易。杠杆交易风险极高，可能导致你的资产价值迅速归零，且无法再增值。**

#### Margin（保证金，当前不可用）

交易在现货市场进行，但交易所借给你与所选杠杆等额的货币。你需要将借出的金额连本带利归还给交易所，你的利润/亏损将按指定的杠杆倍数放大。

#### Futures（期货）

永续合约（也称为永续期货）是以与其基于的标的资产紧密相关的价格进行交易的合约。你并非交易实际资产，而是在交易衍生品合约。永续合约可以无限期持有，这与期货或期权合约不同。

除了期货合约价格变化带来的盈亏外，交易者还会交换 _资金费率_，资金费率的价值来源于期货合约与标的资产之间的价格差异。期货合约与标的资产之间的价格差异因交易所而异。

要在期货市场交易，你需要将 `trading_mode` 设置为 `"futures"`。
你还需要选择一种"保证金模式"（解释见下文）。

``` json
"trading_mode": "futures",
"margin_mode": "isolated"
```

##### 交易对命名

Freqtrade 遵循 [ccxt 的期货命名规范](https://docs.ccxt.com/#/README?id=perpetual-swap-perpetual-future)。
因此期货交易对的命名格式为 `base/quote:settle`（例如 `ETH/USDT:USDT`）。

### 保证金模式

除了 `trading_mode` 外，你还需要配置 `margin_mode`。
虽然 freqtrade 目前只支持一种保证金模式，但将来会有所变化，现在配置好可以确保你为未来的更新做好准备。

可选值为：`isolated` 或 `cross`。

#### 逐仓保证金模式（Isolated）

每个市场（交易对）将抵押品保存在单独的账户中。

``` json
"margin_mode": "isolated"
```

#### 全仓保证金模式（Cross）

使用一个账户在不同市场（交易对）之间共享抵押品。当需要时，从总账户余额中提取保证金以避免清算。

``` json
"margin_mode": "cross"
```

请阅读[交易所特定说明](exchanges.md)以了解支持此模式的交易所及其差异。

!!! Warning "清算风险增加"
    全仓保证金模式会增加全额账户清算的风险，因为所有交易共用相同的抵押品。
    一个交易的亏损可能会影响其他交易的清算价格。
    此外，在全仓模式下，交叉持仓的影响可能无法在模拟或回测模式中完全模拟。

## 设置杠杆倍数

不同的策略和风险配置需要不同的杠杆水平。
虽然你可以配置一个固定的杠杆值，但 freqtrade 通过[策略杠杆回调](strategy-callbacks.md#leverage-callback)为你提供了灵活性——允许你按交易对使用不同的杠杆，或基于其他有利于策略结果的因素进行调整。

如果未实现，杠杆默认值为 1 倍（无杠杆）。

!!! Warning
    更高的杠杆也意味着更高的风险——请确保你完全理解使用杠杆的影响！

## 理解 `liquidation_buffer`

*默认值为 `0.05`*

一个比率，用于指定在清算价格和止损之间放置多大的安全缓冲区，以防止头寸达到清算价格。
这个人工清算价格的计算方式为：

`freqtrade_liquidation_price = liquidation_price ± (abs(open_rate - liquidation_price) * liquidation_buffer)`

- `±` = 对于做多交易为 `+`
- `±` = 对于做空交易为 `-`

可选值为 0.0 到 0.99 之间的任意浮点数。

**示例：** 如果一笔交易以 10 coin/USDT 的价格入场，这笔交易的清算价格为 8 coin/USDT，那么当 `liquidation_buffer` 设置为 `0.05` 时，该交易的最低止损价格为 $8 + ((10 - 8) * 0.05) = 8 + 0.1 = 8.1$。

!!! Danger "`liquidation_buffer` 为 0.0 或较低的 `liquidation_buffer` 很可能导致清算和清算费用"
    目前 Freqtrade 能够计算清算价格，但不会计算清算费用。将 `liquidation_buffer` 设置为 0.0 或使用较低的 `liquidation_buffer` 可能会导致你的头寸被清算。Freqtrade 不跟踪清算费用，因此清算会导致机器人的盈亏结果不准确。如果你使用较低的 `liquidation_buffer`，建议在交易所支持的情况下使用 `stoploss_on_exchange`。

## 不可用的资金费率

对于期货数据，交易所通常会提供期货 K 线、标记价格和资金费率。然而，常见的情况是，虽然 K 线和标记价格可能可用，但资金费率不可用。这可能会影响回测的时间范围，即你可能只能测试近期的时间范围而无法测试更早的，并遇到 `No data found. Terminating.` 错误。要解决这个问题，可以添加[configuration.md](configuration.md) 中列出的 `futures_funding_rate` 配置选项，建议将其设置为 `0`，除非你知道特定交易对、交易所和时间范围的特定资金费率。将其设置为 `0` 以外的值可能会对你策略中的利润计算产生重大影响，例如在 `custom_exit`、`custom_stoploss` 等函数中。

!!! Warning "这意味着你的回测结果将不准确。"
    这不会覆盖交易所提供的可用资金费率，但请记住，设置虚假的资金费率意味着在资金费率不可用的历史时间范围内，回测结果将不准确。

### 开发者

#### 保证金模式

对于做空交易，支付 `借入` 货币利息费用的货币在平仓的同时购买（这意味着做空平仓交易中购买的数量大于做空开仓交易中卖出的数量）。

对于做多交易，支付 `借入` 货币利息费用的货币已由用户持有，无需购买。利息从交易的 `close_value` 中扣除。

所有费用在交易过程中都会计入 `current_profit` 的计算。

#### 期货模式

资金费用要么从交易总额中加上，要么从中减去。
